## 1. Project Description

**Synthetic Market Generator** is an end-to-end quantitative tool for producing realistic artificial market data.

**Problem:** Trading strategies tested against a single historical dataset are prone to overfitting. Robust validation requires stress-testing against many alternative, statistically plausible market scenarios.

**Approach:** Instead of relying on hand-tuned parameters, the system extracts the statistical fingerprint of a real asset directly from historical data:

- **Empirical calibration** — model parameters (drift, volatility, jump intensity) are estimated from data via maximum likelihood estimation (MLE), eliminating human bias.
- **Regime detection** — an unsupervised machine learning model (Hidden Markov Model) discovers distinct market states (e.g., calm vs. turbulent) purely from the data, without manual thresholds.
- **Stochastic simulation** — price paths are generated by a regime-switching stochastic process combining GARCH(1,1) volatility dynamics with Merton jump-diffusion, reproducing well-documented stylized facts of financial markets (fat tails, volatility clustering).
- **Statistical validation** — synthetic output is verified against real data on distributional and time-series properties to prove realism.

**Engineering:** Full-stack application: a Python quantitative core exposed through a REST/WebSocket API, and a web frontend featuring a custom-built HTML5 Canvas rendering engine that animates market generation tick by tick (no third-party charting libraries). Generated datasets are exported in standard formats (CSV/Parquet) for use in external backtesting frameworks (e.g., QuantConnect's LEAN).

**Tagline:** An empirically calibrated Monte Carlo engine that learns how real markets behave — then generates thousands of statistically faithful alternative realities to stress-test trading strategies.

## 2. Tech Stack & Architecture

| Layer | Choice | Notes |
|---|---|---|
| Quant core | Python (NumPy, SciPy, pandas, pyarrow, hmmlearn, arch) | Pure, UI-agnostic package — no API/UI dependencies |
| API layer | FastAPI | REST for calibration profiles & exports; WebSocket for tick-by-tick streaming |
| Frontend | React + TypeScript + Vite | Zustand for state |
| Rendering | Raw HTML5 Canvas 2D (custom engine) | No chart libraries; WebGL only as a later optimization |
| Data | Parquet via pyarrow; historical data via yfinance (start) | EUR/USD and XAU/USD as reference assets |
| Testing | pytest (engine + statistical validation), Vitest (frontend) | The math must be tested, not just the code |

**Monorepo layout:**

```
synthetic-market-generator/
├── engine/          # Python package — the quant core (pure, no API/UI deps)
│   ├── synthetic/   # the actual package
│   └── tests/
├── api/             # FastAPI (Phase 3+)
├── web/             # React app (Phase 3+)
├── data/
│   ├── raw/         # downloaded historical data (untouched)
│   └── processed/   # cleaned, validated Parquet
├── notebooks/       # calibration exploration
└── PROGRESS.md      # cross-session memory: what's done, decisions made
```

**Canonical OHLCV schema (the contract everything obeys):**

```
timestamp (UTC, ns), open, high, low, close, volume
```

Invariants enforced by a validation function: `high >= max(open, close)`, `low <= min(open, close)`, monotonic timestamps, no NaNs.

## 4. Roadmap

### Phase 0 — Foundations

**Goal:** Repository structure and the data contract everything downstream depends on.

- Monorepo setup per the layout above
- Python environment: 3.11+, numpy, scipy, pandas, pyarrow, hmmlearn, arch, pytest, matplotlib, jupyter
- Download historical data for EUR/USD and XAU/USD (yfinance hourly/daily bars as a starting point); save raw files untouched in `data/raw/`
- Define the OHLCV schema and write the validation function
- Build `engine/synthetic/data.py`: raw CSV → clean → validate → Parquet in `data/processed/`
- Write tests for the validation logic
- Create `PROGRESS.md`

**✅ Gate:** Clean, validated OHLCV Parquet files for both assets loadable through the engine's data module, with passing tests.

### Phase 1 — Empirical Calibration

**Goal:** Extract the statistical fingerprint of real assets directly from data — no hand-tuned parameters.

- MLE estimation of baseline parameters (drift μ, volatility σ), then jump-diffusion parameters (jump intensity λ, jump mean/std) — incrementally; this is the hardest math in the project
- HMM regime detection: fit 2–3 Gaussian states on returns/volatility; inspect and characterize discovered states (start with 2 regimes — 3+ gets hard to calibrate and interpret)
- `calibrate(asset) → AssetProfile` function + notebook comparing fitted params vs. reality

**✅ Gate:** Calibrated parameters reproduce the asset's core statistics (mean, volatility, kurtosis) within tolerance.

### Phase 2 — Stochastic Core

**Goal:** Generate synthetic price paths reproducing the stylized facts of financial markets.

- Regime-switching GARCH(1,1) + Merton jump-diffusion simulator, with per-HMM-state parameter sets
- Scenario injection: force a high-variance regime for N candles, then let the Markov chain resume naturally
- `simulate(profile, n_candles, scenario?) → OHLCV[]`
- Statistical validation suite: synthetic vs. real on fat tails (kurtosis), volatility clustering (ACF of squared returns), jump frequency
- Simulate intra-candle ticks and aggregate to bars — one code path serves both animation and export

**✅ Gate:** Synthetic data passes the full statistical validation suite against real market data.

### Phase 3 — Serving Layer & Static Visualization

**Goal:** Expose the engine via API and render output with the proprietary charting engine.

- FastAPI: calibration profiles + simulation endpoints
- Custom Canvas candlestick renderer: axes, dynamic viewport auto-scaling, pan/zoom, dark-mode aesthetics — static first, no animation

**✅ Gate:** 1,000+ candles rendered at 60fps with smooth pan and zoom.

### Phase 4 — The Visual Motor

**Goal:** Live, tick-by-tick simulation of market generation.

- Intra-candle animation: sub-tick price movement, wick formation, dynamic candle close
- WebSocket streaming engine → renderer, generated in non-blocking chunks
- Volume profile + regime heatmap overlay (color background by inferred HMM state — visual proof the HMM works)

**✅ Gate:** A full simulated session animates smoothly from first tick to final candle.

### Phase 5 — Workflow & Export Pipeline

**Goal:** Professional three-step workflow; output usable in external tools.

- Workflow: asset profile selection → resolution/duration → scenario injection (standard path or stress test, e.g., "Flash Crash")
- Reproducibility controls (seeded runs) and scenario presets
- Export to CSV + Parquet, schema-compatible with backtesting frameworks (LEAN)

**✅ Gate:** An exported dataset ingests cleanly into an external backtesting framework.

### Phase 6 — Hardening (Stretch)

- Simulation library with saved, reproducible runs
- WebGL rendering path if canvas bottlenecks
- Multi-asset generation with correlation structure (copula-based)

## 5. Guiding Principles

1. **Quant core first.** The mathematics is the product; the interface is the presentation. A wrong simulator with a pretty chart is worthless.
2. **Validation is non-negotiable.** The statistical test suite (Phase 2) is the project's proof of rigor — budget real time for it.
3. **One code path.** Intra-candle ticks are simulated once and aggregated — serving both the animation and the export.
4. **Everything is gated.** No phase begins until the previous gate passes.
